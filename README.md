# moa-mobile

MOA 자산·접근 관리 제품의 **모바일 앱**. iOS·Android 공통.

**현재 상태: 코드 없음. 설계 문서만 있다.**

**1차 사용처는 모아라 본사다**(2026-10-03 확정). 고객사 납품이 아니라 **자사 도그푸딩**이
먼저라서, 카메라 정책·망 구성·푸시 키·서명 계정이 전부 우리 손에 있다. 착수를 막는 것은
하나뿐이다 — **집의 Mac Pro가 필요한 Xcode를 돌릴 수 있는지**([doc/08](doc/08-결정-대기.md) 2번).
그것도 iOS만 막는다. **Android는 지금 시작할 수 있다.**

서버(MOA)는 별도 레포 `D:\project\ai\moa`에 있다. 이 앱은 그 서버의 화면을 쓰며,
**새 API 서버를 만들지 않는다**(이유는 [02-아키텍처](doc/02-아키텍처.md)).

---

## 한 장 요약

| 항목 | 결정 |
|---|---|
| 앱 형태 | **Capacitor 껍데기 + 웹뷰**. 네이티브는 푸시·카메라·생체만 |
| 왜 | 서버가 Thymeleaf SSR(화면 89개)이다. 웹뷰로 감싸면 UI를 다시 만들지 않고 API 계층도 필요 없다 |
| 새로 만드는 서버 | **푸시 릴레이 하나**(DMZ, 엔드포인트 1개, 무상태) |
| 인증 | 서버의 기존 세션 쿠키. **토큰 계층 없음.** 2차 승인은 TOTP + (선택) 기기 하드웨어 키 |
| 앱의 두 역할 | **승인 채널**과 **현장 단말**. PC의 축소판이 아니다 |
| 고객 환경 차이 | **빌드 플레이버로 흡수.** 소스에 박지 않는다 |
| 배포 | 1차 자사 — iOS TestFlight 내부 테스터 · Android APK 직접. 고객사는 MDM |

**가장 중요한 한 줄**: 대역 외 승인은 카메라가 필요 없어서, 카메라를 막는 고객(국방부)에게도
앱이 값어치를 갖는다. QR보다 이것이 앱의 주된 명분일 수 있다.
