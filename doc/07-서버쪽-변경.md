# 07. 서버쪽 변경

이 앱이 동작하려면 서버 레포(`D:\project\ai\moa`)에 해야 하는 작업이다.
**앱 코드보다 이쪽이 먼저다** — 붙을 화면이 없으면 앱을 만들 수 없다.

서버 기준: **0.9.6-SNAPSHOT**, 스키마 V73.

## A. 앱이 성립하려면 필수

| # | 항목 | 내용 | 크기 |
|---|---|---|---|
| **P1** | **`/m/**` 경로 신설** | nginx 화이트리스트의 전제. 모바일 컨트롤러 + 모바일 템플릿. `SecurityConfig`에 규칙 추가(역할 조건은 기존과 동일하게 이중 방어) | 중 |
| **P2** | **앱 능력 읽기** | User-Agent의 `caps=` 파싱 → 메뉴 결정. `GlobalViewAdvice`에 얹으면 모든 뷰에서 쓸 수 있다 | 소 |
| **P3** | **⚠️ XFF 신뢰 처리** | 프록시 뒤에서 `ClientIpResolver`가 스푸핑 가능([02](02-아키텍처.md)). nginx가 덮어쓰는 것을 전제로 하되, **신뢰 홉 수를 설정으로 받는 방식이 더 안전** | 소 |
| **P4** | **세션 쿠키 강화** | `cookie.secure=true`, `same-site=lax`. TLS 도입과 한 묶음(MVP B1) | 소 |
| **P5** | **기기 토큰** | `device_tokens(tenant_id, user_id, platform, token, caps, registered_at)` + 등록 엔드포인트 1개 + 사용자별 기기 목록·폐기 화면 | 중 |
| **P6** | **step-up 게이트** | `@StepUpRequired("행위코드")` + 인터셉터 + `stepup_requests` 테이블. **기존 PC 컨트롤러에 애노테이션을 붙이는 작업이 따라온다**(자격증명 열람·솔루션 제어·권한 부여·퇴사) | 대 |
| **P7** | **알림에 종류 추가** | `Notification`에 `kind` 없음(현재 title/body/link/read만). 무내용 푸시의 딥링크와 앱 내 분류에 필요 | 소 |

## B. 새로 필요한 데이터 모델

| # | 항목 | 왜 |
|---|---|---|
| **P8** | **`asset_tags(code, item_id, tenant_id, issued_at, attached_at)`** | QR 스티커 코드는 자산과 **분리**해야 한다 — 미부착 스티커를 미리 대량 발급하므로. 코드는 전역 유니크 + 조회 시 기관 검증(다른 기관 스티커로 남의 자산이 보이면 격리가 깨진다) |
| **P9** | **첨부 일반화** | 현재 `WikiAttachment`는 **위키 전용**. `attachments(owner_type, owner_id, ...)`로 일반화해 자산·점검·고장신고가 함께 쓰게 |
| **P10** | **점검 결과 기록** | `MaintenanceWindow`는 **일정만**(title/reason/startsAt/endsAt). 체크 항목·결과·사진·수행자를 남길 자리가 없다 |
| **P11** | **고장·이상 신고** | 소모품 요청 구조(요청 → 확인/거절/보류(사유) → 요청자 알림)를 재사용 |
| **P12** | **생체 등록 키** | `device_keys(user_id, device_id, public_key, algo, enrolled_at, revoked_at)`. P5와 합칠 수도 있다 |
| **P13** | (2차) **실사 세션** | `stock_counts` + 스캔 이력. **P8 설계 때 자리를 비워 둔다** |

## ⚠️ P8은 서버의 관리번호 작업과 같은 것이다

서버 레포 `doc/실무자료-기능제안-20260925/05-코드대조-검토.md`의 **M-I02(자산대장 필드 보강)**가
실무 자산대장의 **관리번호**를 추가하자고 한다. 그리고 여기 P8은 QR 스티커 코드다.

**둘은 같은 것이다.** 따로 만들면 **한 장비에 식별자가 둘** 생기고, 현장에서 "이 번호로 찾아
주세요"가 통하지 않는다.

> **M-I02를 착수할 때 이 문서의 P8을 함께 열어야 한다.** 관리번호를 `InventoryItem`의 단순
> 컬럼으로 추가하면 나중에 뒤집는다.

그리고 서버 쪽에 **이름 유일성 제약**(`requireUniqueName`)이 있어서 "개발용PC" 5대를 등록할 수
없다 — 관리번호 도입과 함께 **유일성의 책임을 이름에서 관리번호로 넘겨야** 한다.

## C. 앱을 생각하다 드러난 서버의 구멍

**앱 때문이 아니라 원래 있어야 했던 것들이다.**

| # | 항목 | 현재 |
|---|---|---|
| **P14** | 자격증명 열람에 step-up이 없다 | 서버 `AGENTS.md`는 "볼트는 사용 시 step-up을 거친다"고 요구하는데 `resolveSecret`에 게이트가 없다. `TwoFactorService.verify`는 "후속 step-up 게이팅용"이라 주석까지 달린 채 미연결 |
| **P15** | 자산에 사진이 없다 | 첨부가 위키에만 있다. PC에서도 아쉬운 구멍 |
| **P16** | 점검 일정만 있고 결과가 없다 | 점검을 했는지 안 했는지 알 수 없다 |
| **P17** | 고장 신고 경로가 없다 | 메신저·구두로 오고 기록이 없다 |
| **P18** | 퇴사 시 열린 세션이 안 끊긴다 | 알려진 한계. **모바일 토큰이 생기면 더 커진다** — 기기 토큰 폐기가 퇴사 처리에 포함돼야 한다 |

**P18이 모바일 때문에 커지는 유일한 기존 한계다.** 지금은 "로그인만 막힌다"가 끝이지만,
앱에 푸시 토큰과 생체 키가 등록된 뒤에는 퇴사 처리가 그것들도 폐기해야 한다.

## 순서

```
0. MVP 마무리 — TLS(nginx) · 볼트키 절차 · 테스트기관 정리
   └ 이 nginx 작업이 곧 DMZ 중계다
   └ P3(XFF) · P4(쿠키)를 이때 함께

1. P1 /m/** + P2 능력 읽기          ← 모든 모바일 기능의 토대
2. P6 step-up + P14 볼트 게이트      ← 보안 가치 최대. 앱 없이 PC 코드입력으로도 동작
3. P5 기기 토큰 + 푸시 릴레이 + P7   ← 알림
4. P8 QR 체계 + P9 첨부 일반화       ← 현장 기능의 토대. M-I02와 함께
5. P10 점검 결과 · P11 고장 신고
6. (2차) P13 실사
```

**2번은 앱이 없어도 값어치가 있다** — PC에서 Authenticator 코드를 입력하는 경로만으로
볼트 step-up이 완성되므로, 앱 착수와 무관하게 먼저 해도 된다.
